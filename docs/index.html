Clean commits.
With the agent you already use.

Turn your changes into clear commit messages, or split them into logical commits. Review the proposal, make it yours, and ship. 

$ brew install saadjs/tap/commit-cli
Quick start ↓Explore the flags →GitHub ↗

Supports Claude, Codex, OpenCode, and Pi. The agent proposes text; commit-cli runs every Git command.

01Install

brew install saadjs/tap/commit-cli

Or install from source (Node.js 20.19+):

git clone https://github.com/saadjs/commit-cli.git
cd commit-cli
npm install && npm run build && npm link

You also need at least one of claude, codex, opencode, or pi on your PATH. Check which providers are available with: 

commit --providers

02Quick start

commit                       # propose one commit
commit --split               # split changes into logical commits
commit -m "fix the race"    # give the agent a hint
commit --dry-run             # preview without committing
commit --push                # commit and push the branch
commit --pr                  # commit, push, and open a GitHub PR
commit -b --pr --draft       # create a branch and open a draft PR

After the proposal, choose yes, edit, regenerate, or no. Use -y to skip the confirmation.

Common commands

Command Action
commit Use staged changes; if nothing is staged, stage tracked changes.
commit -a Stage tracked changes plus untracked files.
commit <paths...> Commit only the named paths, including untracked files.
commit -x '*.lock' Exclude matching paths; repeatable.
commit -b Ask the agent for a branch name and commit on that new branch.
commit --branch-name <name> Commit on an explicitly named new branch (implies -b).
commit -P codex Use a specific provider.
commit --model <id> Override the provider's model.
commit --no-verify Skip git commit hooks.
commit --config Show resolved settings and their sources.

Paths are git pathspecs, so globs and :(exclude) syntax work. Run commit --help for every option.

Creating a branch

Use -b / --branch to have the agent propose a branch name alongside the commit messages. The proposal shows → new branch: <name>; y approves both, n aborts without creating a branch, and r regenerates both. e edits only the messages and keeps the proposed branch name.

--branch-name <name> skips asking the agent for a branch name; the agent still writes the commit messages. Explicit names are used unchanged and must be valid, unused Git branch names. Generated names are normalized to lowercase kebab-case, kept under 50 characters, and given a numeric suffix when needed to avoid existing local branches. If the agent supplies no usable name, commit-<timestamp> is used.

With --split, the branch is created once, after approval and all message edits, before the first commit. -y approves automatically. --dry-run shows the name without creating a branch or commit; the usual staging behavior still applies. If a commit hook fails after branch creation, you remain on the new branch with your uncommitted changes available.

03Flag reference

Usage: commit [options] [paths...]. Flags are case-sensitive: -P selects a provider; -V prints the version.

paths...

Optional Git pathspecs. Only named paths are committed, including untracked files; other staged changes are unstaged. Globs and :(exclude) syntax work. Use -- before paths beginning with a dash.

--message -m <hint>

Give the agent context about the change. This is a hint, not a literal commit message. Also informs PR generation.

--all -a

Stage tracked changes and untracked files. Named paths take precedence when supplied.

--exclude -x <path>

Leave matching paths out by unstaging them. Repeatable; accepts Git pathspecs and globs. Adds to config exclusions. Quote globs, for example -x '*.lock'.

--branch -b

Ask the agent for a new branch name and commit there after approval.

--branch-name <name>

Use an explicit new branch name; implies --branch. Must be a valid, unused Git branch name.

--split

Split changes into logical, file-level commits. Defaults to false unless enabled in config. Does not preserve hunk-level staging; there is no --no-split override.

--push

Push the current branch after committing. Also works with already committed changes. Sets upstream; never force-pushes.

--pr

Push and create a GitHub PR using an installed, authenticated gh CLI. Reuses an existing open PR for the branch and base.

--draft

Create a draft PR. Requires --pr; new PRs are ready for review by default.

--base <branch>

Choose the PR base. Requires --pr. Defaults to the GitHub repository’s default branch.

--remote <name>

Choose the push remote. Requires --push or --pr. Defaults to the branch’s configured remote, otherwise origin.

--yes -y

Approve committing and publishing without confirmation. Needed for noninteractive use unless previewing with --dry-run.

--dry-run

Preview without creating branches, commits, pushes, or PRs. Still stages files; PR previews check GitHub and fetch the base.

--provider -P <name>

Select claude, codex, opencode, or pi. Built-in default: claude.

--model <id>

Override the selected provider’s model for this run. Takes precedence over environment and config.

--no-verify

Skip Git commit hooks.

--timeout <sec>

Set the provider timeout in positive, finite seconds (fractions accepted). Default: 180, or the configured timeoutMs converted to seconds.

--providers

List providers, installation status, and built-in default models, then exit.

--config

Show resolved config, model settings, source files, and value origins, then exit. Run inside a Git repository. This report includes environment overrides, but does not apply other command-line overrides.

--verbose -v

Print the raw provider response for debugging.

--help -h

Show usage and all options, then exit.

--version -V

Show the installed version, then exit.

04Pushing and pull requests

Push your branch or open a GitHub PR. Both work with already committed changes. PRs require an installed, authenticated gh CLI. 

commit --push                              # push after committing
commit --pr                                # push and open a PR
commit -b --pr --draft                      # new branch, draft PR
commit --pr --base develop --remote origin  # choose destination
commit --pr --dry-run                       # preview
  • Review first. The agent writes PR text from the full branch diff and your repository template. Approve, edit, regenerate, or cancel before pushing. -y skips confirmation.
  • Existing PR? Pushes updates and prints its URL; keeps its title and description.
  • Use a feature branch. Add -b when on the default branch. Only same-repository PRs are supported.
  • Cancel or retry. Local commits are kept. After a publishing failure, fix the issue and rerun. Pushes are never forced.

--dry-run still stages files and fetches the PR base. See the flag reference for defaults and option requirements.

05What gets committed

Situation Files committed
Something is already staged Exactly the staged changes, unless excluded.
Nothing is staged All tracked changes.
-a is used Tracked changes and untracked files.
Paths are provided Only those paths; they are staged for you.
-x is used Matching paths are left out.

06Providers

The default provider is claude. Override it with -P or set COMMIT_PROVIDER. Each provider uses its own CLI and default model:

Provider CLI Default model
claude claude -p haiku
codex codex exec gpt-5.6-luna
opencode opencode run opencode-go/gpt-5.6-luna
pi pi --print opencode-go/gpt-5.6-luna

Override models per run with --model, or in your config.

07Configuration

Settings are applied in this order, with later values winning:

  1. Built-in defaults
  2. Global config: $XDG_CONFIG_HOME/commit-cli/config.json (usually ~/.config/commit-cli/config.json)
  3. Repository config: .commitrc.json
  4. COMMIT_PROVIDER / COMMIT_MODEL
  5. Command-line flags

models and exclude merge between config files; other settings replace earlier values. Example: 

{
  "provider": "claude",
  "models": { "claude": "sonnet" },
  "split": false,
  "exclude": ["*.lock", "dist/"],
  "timeoutMs": 180000,
  "instructions": "Mention the ticket ID when there is one."
}

Available keys: provider, models, split, exclude, maxDiffBytes, timeoutMs, and instructions. Invalid keys and values are rejected with an explanation.

Configuration keys

Key Type / default Behavior
provider string / claude One of the four supported providers.
models object / provider defaults Map provider names to model IDs. Maps merge across config files.
split boolean / false Enable file-level split commits by default.
exclude string[] / [] Git pathspecs to omit. Lists merge and deduplicate; -x adds more.
maxDiffBytes positive number / 200000 Maximum diff bytes sent to the agent. Full diffstat is always included.
timeoutMs positive number / 180000 Provider timeout in milliseconds. --timeout uses seconds.
instructions string / unset Additional guidance for commit and PR generation.

Environment variables

COMMIT_PROVIDER selects the provider; COMMIT_MODEL selects its model. XDG_CONFIG_HOME changes the global config directory. Editor selection uses GIT_EDITOR, then VISUAL, then EDITOR, falling back to vi.

08Editing and caveats

  • e opens COMMIT_EDITMSG using $GIT_EDITOR, then $VISUAL, then $EDITOR (or vi). Saving an empty message or using :cq aborts; quitting without changing the message accepts it unchanged.
  • --split re-stages files commit by commit, so it does not preserve hunk-level staging. Plain commit does.
  • Large diffs are truncated at maxDiffBytes (200,000 bytes by default); the full diffstat is always sent to the agent.

09Development

npm install
npm run build
npm link

Run the build and unit tests with:

npm test

The test suite does not require provider credentials or model calls.

To add a provider, implement Provider in src/providers/ and register it in src/providers/index.ts. The provider returns text; prompting, parsing, staging, and committing are handled by the core.

Release notes

homebrew/commit-cli.rb is the source of truth for the Homebrew formula. A release tag builds the tarball, attaches it to GitHub, and updates saadjs/homebrew-tap. 

npm version patch
git push --follow-tags

The workflow requires a HOMEBREW_TAP_TOKEN repository secret with write access to the tap repository.
